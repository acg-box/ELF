# RAGFlow document comparison

RAGFlow, Hindsight, and ELF each answered all twelve new document-precision
questions correctly. This small text workload does not establish a unique
RAGFlow advantage for document retrieval, nor an inevitable loss of details in
Hindsight's fact extraction. RAGFlow's default retrieval profile did fail all
six source-authority questions and all six temporal-correction questions.
Keep those failures when evaluating the product.

## Native deployment and scope

The latest GitHub release checked on October 9 was `v1.0.0-rc1`. Both the server
and benchmark clients ran in Docker. The official AMD64 image was pinned to
`sha256:31ccf0336d8910f6d90ac7d4fff766cc0483ec10042b906a377f27bfe09f818b`.
The host uses ARM, so this condition uses emulation. The API confirmed its Go
backend. Upstream source was `14bb02ee4584c1ab18f0c722c48beecd6bbf9860`.

The official Compose configuration lists OpenSearch, but the Go server rejected
it at startup with `not implemented: opensearch`. The completed condition uses
Infinity, MySQL, Kvrocks, NATS, object storage, and ClickHouse. This does not
validate a PostgreSQL plus OpenSearch deployment or an AIP integration.
The startup failure is deployment evidence, not a retrieval score.

Embedding used Qwen3 Embedding 8B through Nebius at 1,536 dimensions. The shared
reader used DeepSeek V4.1 Flash with low reasoning. Retrieval used the native
hybrid path, a 0.2 similarity threshold, 0.3 vector weight, five returned chunks,
and no reranker. General text parsing used native defaults, including filename
embedding. Source filenames were opaque benchmark evidence identifiers.
Native Memory, Agent, knowledge compilation, and synthesis were not measured.

## Behavior results

| Capability | RAGFlow correct/planned | ELF historical comparison | Hindsight historical comparison |
| --- | ---: | ---: | ---: |
| Cross-session retrieval | 6/6 | 5/6 | 6/6 |
| Authoritative source selection | 0/6 | 6/6 | 6/6 |
| Current fact after a temporal correction | 0/6 | 6/6 | 6/6 |
| Two populated native scopes | 12/12 | 12/12 | 12/12 |
| Source replacement, separate recovery condition | 6/6 | 6/6 | 6/6 |
| Source deletion, separate recovery condition | 6/6 | 6/6 | 6/6 |

RAGFlow's first four rows use the thirty nonmutation cases in `behavior-v6`.
All 24 conflict documents had completed native ingestion and one chunk each.
For authority questions, the top five contexts contained informal proposals
and omitted the signed policy. The reader returned `unknown`. For temporal
questions, the contexts contained retired records and omitted the corrections.
The reader answered with the retired values. These are retrieval failures in
this profile; they are not evidence of missing source ingestion or a general
inability across all RAGFlow configurations.

The original behavior condition ran all 42 queries, but its twelve mutation
operations failed because the adapter queried deleted IDs. The API rejects
those IDs instead of returning an empty list. Its raw 24/42 answer count is
retained, but is not a valid complete lifecycle score. The corrected adapter
checks the owned dataset listing. The independent `mutations-v1` condition
completed all six replacements, six deletions, and twelve queries correctly.
Replacement uses delete plus upload, not an atomic in-place source update.
No incorrect authority or temporal answers were selectively retried.

The source changed during the invalid mutation tail of `behavior-v6`.
The ingestion, query, workload, and reader paths did not change. The nonmutation
prefix is reported separately, and the complete mutation group was rerun on a
clean signed source revision. Do not combine these into a single clean-run claim.

ELF and Hindsight behavior columns come from the unchanged October 8 evidence.
They share question identities and scoring but are historical conditions, not
new same-provider runs. ELF's cross-session failure occurred after the expected
fact was retrieved. The new document comparison below does use the same current
model and provider profile for all three targets.

A separate native access probe used another task-owned user. Both dataset access
and retrieval were rejected with business code 102. HTTP status was 200, so
clients must check the business result. This is cross-user denial evidence,
not proof of permission revocation, physical erasure, or an application's ACLs.

## Same-source document comparison

Eight synthetic text documents contain complete return-policy exceptions and
regional routing tables. Twelve questions test four exception lists, four table
rows, and four absent facts. Each target received the same inputs and oracle.

| Target | Exception lists | Table rows | Absent facts | API cost for this condition | Observed condition time |
| --- | ---: | ---: | ---: | ---: | ---: |
| RAGFlow 1.0.0-rc1 | 4/4 | 4/4 | 4/4 | $0.002225 | 110 seconds |
| Hindsight 0.10.2 | 4/4 | 4/4 | 4/4 | $0.024573 | 333 seconds |
| ELF existing pinned image | 4/4 | 4/4 | 4/4 | $0.002019 | 144 seconds |

These timings include different startup paths. RAGFlow's separate server was
already running, while Hindsight and ELF dependencies started for each
condition. RAGFlow also used AMD64 emulation. Do not infer production throughput
or a general speed ratio from this table. Costs are actual provider receipts,
including cache pricing; they exclude host compute and orchestration.
Hindsight completed native consolidation before queries. Its extra processing
cost in this condition is measurable, but is not a universal cost multiplier.

All eight answerable questions had their expected facts in the supplied contexts.
The other four were correctly answered `unknown`. Native document identities
map contexts to expected evidence. The shared reader does not emit a complete
citation UI, so this is not an end-user citation-presentation test.
The tables are plain text, not binary spreadsheets. There are no scanned PDFs,
OCR, long contracts, cross-document joins, multilingual sources, or real customer
data in this condition. Twelve questions are insufficient for a broad ranking.

## Setup failures, cost, and cleanup

Six initial behavior attempts remain distinct. They record Compose validation,
model-instance selection, the ordinary OpenAI driver's private-address guard,
Go ingestion-status handling, pagination, and mutation-readback errors.
The supported OpenAI-API-Compatible driver connects to the local budget gateway;
no address guard was disabled. The original failures and denominators remain.
`setup-dispositions.json` explains which failures belong to the adapter.

The complete extension cost **$0.036217834**, including preparation attempts and
all comparisons. The cumulative campaign paid **$15.087162377**, with conservative
exposure **$15.401944377**, below the authorized $20 ceiling. All 511 new provider
requests completed and no new uncertain charge was added. Earlier unknown
charges remain reserved. No paid process remains.

Cleanup removed eight task-owned server containers, seven volumes, the native
network, and eight newly downloaded unused images. All ten deep-condition
projects are absent. Docker's reported image usage fell from 16.21 GB to
11.54 GB, and volume usage from 21.68 GB to 19.65 GB: about 6.7 GB of tracked
Docker storage. This is not a claim that the host VM disk file shrank by the
same amount. Unrelated containers, legacy data volumes, and other projects'
build caches remain. Ephemeral native session credentials were removed.

The published evidence has ten conditions and 300 case rows, including failed
and repeated attempts. It does not contain 300 independent questions. Artifact
hashes, source and image identities, contexts, operations, usage, and cleanup
receipts accompany the results. The original campaign evidence is unchanged.

## Implication for the product decision

Keep RAGFlow as a document-retrieval comparison target. This test supports its
basic source retrieval, source replacement, deletion, and traceable native
contexts. It also demonstrates the need to test source authority and temporal
corrections separately from simple fact lookup.

The equal document scores do not justify operating two engines by themselves.
A decision to add RAGFlow to an existing Hindsight deployment needs evidence of
additional value on representative documents, especially parsing and exact
source handling. The latest Go release also needs explicit backend compatibility
checks before use with an OpenSearch deployment. These measurements do not decide
an AIP production migration.
